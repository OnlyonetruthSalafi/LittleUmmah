# C-0 — สำรวจเนื้อหาทุกเกาะ + เสนอแพ็กเกจเพิ่มเนื้อหา
model: gpt-6-astra · effort medium · อ่านอย่างเดียว (-s read-only)

## บริบท
เจ้าของโปรเจกต์สั่ง (8 พ.ย. 2026): "เพิ่มเนื้อหาในเกาะต่างๆ ให้มากขึ้น" Claude จะวางแผนและแตกเป็นแพ็กเกจให้ Codex ทำ
อ่าน `D:/Littleummah/AGENTS.md` ทั้งไฟล์ก่อน (โดยเฉพาะข้อ 1 นโยบายเนื้อหา, 1.6 แหล่งนิทาน, ข้อ 2 UX)

## ขอบเขต
ใน `D:/Littleummah` (main 197aae4) สำรวจทุกเกาะ: `src/features/{explore,moral,stories,arabic,art,games}` + หน้าใน `src/app/[lang]/` + asset ใน `public/` + สคริปต์ที่เกี่ยว (`scripts/make-*-voice.mjs`, `scripts/check-*-browser.mjs`, `scripts/optimize-images.mjs`)

ส่งรายงาน:
1. **ตารางเนื้อหาปัจจุบัน** ต่อเกาะ: จำนวนบท/ด่าน/รูป/ฉาก แบ่งตามช่วงวัย (kids 3–6 / juniors 7+), ไฟล์ข้อมูล, รูปแบบข้อมูล (type), asset ต่อหน่วย (ภาพ, เสียงพากย์ ไฟล์ไหน), pipeline ที่ใช้สร้าง (brief เดิมใน `docs/briefs/archive/` หรือรากโปรเจกต์)
2. **ช่องว่างที่เห็นชัด** เช่น หมวดที่มีแค่ 1–2 บท, ช่วงวัยที่เนื้อหาน้อย, การ์ด "เร็วๆ นี้" ที่ยังไม่มีของ
3. **แพ็กเกจเพิ่มเนื้อหาที่เสนอ** 6–10 แพ็ก แต่ละแพ็ก:
   - ชื่อ, เกาะ, เพิ่มอะไรกี่หน่วย (ตัวอย่างหัวข้อจริง)
   - **ติดป้ายศาสนา**: `ไม่มี` (ไม่มีอายะฮ์/หะดีษ/ดุอาอ์/เรื่องศาสดา) หรือ `REVIEW-RELIGIOUS` (ต้องให้ Claude ตรวจตัวบทกับ Shamela)
   - asset ที่ต้องสร้าง (ภาพ Codex imagegen, ภาพถ่าย CC0/PD, เสียงพากย์ ElevenLabs ผ่านสคริปต์เดิม) และความเสี่ยงตามข้อ 1.1/1.3/1.5
   - ไฟล์ที่ต้องแก้, เวลาประมาณ, เกณฑ์ผ่าน (สคริปต์ตรวจที่มีอยู่)
   - เรียงลำดับ: แพ็กที่ไม่มีศาสนาและใช้ pipeline เดิมได้ก่อน
4. ข้อจำกัด: เสียงพากย์ต้องใช้ API key ElevenLabs ไหม อยู่ที่ไหน (บอกแค่ว่ามี/ไม่มี ห้ามพิมพ์ค่า key), การอ่านอาหรับด้วยเสียงสังเคราะห์ (ข้อ 1.6 และแผน P5-3 ต้องมีผู้รู้ตรวจ)

## ห้าม
- แก้ไฟล์ใดๆ, commit, เปิด server
- ตัดสินเนื้อหาศาสนา (ติดป้ายแล้วข้าม)
- เสนอการ์ตูนมีเด็ก (แม้หันหลัง) ในเกาะมารยาท — ใช้หุ่นยนต์เท่านั้น; รูประบายสีเป็นสิ่งของ/พืชเท่านั้น
